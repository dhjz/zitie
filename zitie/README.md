# zitie · 字帖工坊

纯前端离线字帖生成器。双击 `index.html` 就能用，不需要安装、打包或联网。

## 目录

```
index.html        根组件模板
static/
  app.css         界面样式 + 打印版面
  utils.js        工具层：笔顺解码 / 拼音 / 出题 / 分页排版
  store.js        配置层：schema 注册表、自动保存、导出导入、恢复默认
  ui.js           组件层：控件、A4 纸张、格子
  index.js        入口：路由、主题、装配
  page.*.js       各功能页（自注册进 window.myComponents）
  collection.js   素材合集：弹窗、页签、方格点选与复制
  page.settings.js 设置弹窗：导出 / 导入 JSON、恢复默认
  data/           笔顺数据、笔心线数据、拼音引擎、素材合集数据、课文生字表
  fonts/          中文六款、英文四款、拼音两款、控笔线条一套
```

## 加一个页面

1. 拷一份 `static/page.hanzi.js`，改成 `page.xxx.js`
2. 在 `DEFAULTS` 底下加一行 `Z.settings.define('xxx', { label, defaults: DEFAULTS, inputs: ['content'] })`
3. 末尾写 `window.myComponents.XxxPage = XxxPage`
4. `index.html` 里补 `<script src="static/page.xxx.js">`
5. `static/index.js` 的 `ROUTES` 加一项，模板里加 `<xxx-page v-else-if="route === 'xxx'">`

`index.js` 本身不用改 —— 组件是自注册的。

首页那张缩略图同理：`ui.js` 里的 `THUMBS` 加一份该页的小样数据
（几行几列、哪些字描红），`page.home.js` 的 `features` 里加一张卡就成。
缩略图是 SVG 按真实字帖比例画的，不拉笔顺分片。

## 中文字体：描字走字体，笔顺走笔画

汉字字帖的「字体」选择只对描字有效，因为它和笔顺是两条完全不同的渲染路径：

- **描字（`render: 'text'`）** 用 SVG `<text>` 按选中字体整字画。选隶书就是隶书，选行楷就是行楷。
- **笔顺 / 笔顺条（`render: 'stroke'`）** 画的是笔顺数据里的笔画轮廓路径，一个字拆成一笔一笔。数据只有楷体那一套，所以这两档下字体选项没有意义 —— 换到非楷体时它们会置灰。

词语文章页同理，整段文字只走字体（`genStage` 固定 `render: 'text'`），
逐笔拆一整篇课文既看不出来也没必要。

顺带一个性能收益：描字和词语文章不再需要笔顺分片，`useGen` 的 `strokes` 判定会让它直接跳过预取
（`font_type === 1` 才跳过；笔顺、笔顺条都要拆笔，得先把分片拉齐）。

### 六款字体怎么对齐到同一个格子

各款字体在 em 框里画得多满差很多 —— 隶书的字只占 em 高 65%，仿宋能到 98%，
行楷还往下探出 20%。字号直接取格子边长，同一版面上就会「有的顶天立地、有的瘦一圈」。

所以 `Zu.fontMetric(key)` 会用 canvas `measureText` 量一批常用字的墨迹包络
（95 分位，避开「永」「春」这类挑出去的字），反算两件事：

- `scale`：字号缩放，让墨迹占格子的 88%（留出走笔空间）
- `baseline`：基线位置，让墨迹中心落在格子正中

量好缓存起来，字体是 `FontFace` 异步注入的，所以先给个近似值、量完 bump `Zu.metricRev` 让字形重排。
用 canvas 而不是 SVG `getBBox` —— 后者在 Chrome 里返回的是 em 框（永远 1000×1000），量不出实际墨迹。

## 笔顺条：字头 + 整行描红

作业本上常见的那种排法：一行字头（大字 + 拼音 + 一溜笔顺小图），下面整行描红。
这就是「格式」的第三档 `font_type: 3`，`genHanzi` 里叫 `strip`。

- **字头行**是一个 `{ kind: 'headbar' }` cell，CSS 上 `grid-column: 1 / -1` 跨满一行。
  里面左边大字头、右边一排 `ZGlyph mode=stroke upTo=i` 的小图，一个字几画就排几个；
  超过 16 画自动把图缩一档，免得挤出第二行。
- **描红行**沿用原来的「几行描 + 几行空」，或者「间隔描字」的模式；
  第一行第一格照旧深色示范，跟其它格式一个规矩。
- **拼音**搬到字头行里，格子里不再留拼音行 —— 所以 `doc.pinyin` 在这一档是 `false`，
  页面上的「拼音格」选项也跟着藏起来。

分页有个坑：字头是**跨整行的一格**，如果按 1 格算，「1 行字头 + 3 行描红」看着才 4 格，
实际占了 4 行，一页会塞进双倍的块。所以 `Z.paginateBlocks` 多了个 `weight` 参数，
`genHanzi` 传 `(c) => (c.kind === 'headbar' ? cols : 1)`，补齐每页时也按权重量。

## 格型、描字类型、页脚、订正格

这四项都是「加一个选项就看得见」的那种，落在 `doc` 上，`ZSheet` 照着画。

**格型**（`doc.guide`）是 `.cell-guide` 上的一个 class，纯 CSS：

| key | 名字 | 画法 |
|---|---|---|
| `tian` | 田字格 | 十字虚线 |
| `mi` | 米字格 | 十字 + 对角线 |
| `hui` | 回宫格 | 内缩虚框 |
| `cross` | 交叉格 | 只有对角线 |
| `fang` | 方格 | 只有外框 |
| `jiu` | 九宫格 | 四线切九块 |
| `shuang` | 双横线 | 抄写本横线页，去掉竖线 |
| `wu` | 无格 | 一片白纸 |

九宫格那四条线用四层 `linear-gradient` 画，不用伪元素 —— 只有两个伪元素，不够切九块。

**描字类型**（`doc.trace`）一共十一档，示范格永远是实心，选项只改练习格。
根子上一句话：**CSS 描不了字形轮廓，但 SVG 的 `stroke` 可以；而轮廓里没有「笔从哪走」
这件事 —— 那得靠笔心线。** 所以分两条路子：

- **轮廓路线**（`stroke` + `dash`）：空心、空心虚线、细实线，描的是字形的边。
  字体整字（描字帖、词语文章、英文、拼音）只能走这条 —— 一条属性换几种字帖，
  不用另存一套空心字体。
- **笔心线路线**（`mw` + `mdash` + `clip`）：细虚线、细虚线·密、点虚线、填充虚线、
  擦除画、浅底擦除，全是在笔心线上画一条带子。宽的（填充虚线 191、擦除 153）
  拿轮廓当裁切区裁掉出界的部分，剩下的就是一道笔迹；窄的（细虚线 38）本来就是细带。

汉字那边只有「笔顺」格式和数字字帖有笔心线（都是矢量字形），所以
填充虚线、擦除画、浅底擦除在描字帖 / 词语文章里是灰的。参数表在
`Zu.TRACE_SPEC`，两条路子的宽度各写一份（`stroke` 给轮廓、`mw` 给带子、
`fstroke` 给字体整字按字号折算的那份），值照原站换算，原站格子基准 670px、
我们的字形是 1024 方格，乘 1.528。

**擦除画**是沿笔心线挖一条白槽（宽 34）穿过笔画，只剩两侧的边 —— 练「笔尖走哪条道」。
白线在白纸上本来什么都看不见，所以底下垫一层淡轮廓（擦除画 0.85、浅底擦除 0.24）。

**页脚**（`doc.foot`）是姓名 / 班级 / 日期几栏，给交作业用。页码一直有，
开了页脚就压到右边，不跟姓名挤。

页脚印哪几栏在每页的「页脚」里选，五档：不要 / 姓名 / 日期 / 姓名日期 / 姓名班级日期。
编号是 `0 / 3 / 4 / 1 / 2` —— 1、2 是老存档里的「姓名日期」「姓名班级日期」，
换号老用户一进页面页脚就错，所以新加的两档排在后面。

**姓名和日期本身不归页面管**，归顶栏齿轮里的「全局设置」（`zitie:global`，
`Zu.global` 是一份 reactive，改完预览立刻重排）：

- 姓名填了就印在姓名那一栏，留空仍是一条 `22mm` 的留白横线给手写
- 「自动生成日期」打开就印当天（`YYYY-MM-DD`），关着同样留横线

一份全局配置，八个页面共用；导出 JSON 时挂在 `global` 字段上，导入时一并回灌。

**订正格**（`doc.fixH`）每页底部留一行「改错」区。高度不是白送的：`gridFor` 多收一个
`reserve` 参数，先把它从版心里扣掉再排行数，所以格子照样铺满、不会多出一页来。
页脚和订正格都只在 `doc` 上挂字段，各页面把选项原样传进去，不着渲染层的事。

## 间隔描字、拼音格样式、空段、逐字注音

第一梯队那四项是「加个选项就看得见」，第二梯队这四项动的是排版的节奏。

**间隔描字**（`form.row_pattern`）一行一个记号，`描`/`空`（也认 `t`/`b`、`1`/`0`）。
「描描空」就是这个字印两行淡字、留一行自己写。填了它就不看「几行描 + 几行空」；
模式的第一行兼作示范行，第一个格子深色、其余淡色。最多 8 行。
笔顺帖不走这条路 —— 那儿一格里是一笔，跟「一行整字」不是一个东西。

**拼音格样式**（`doc.pyStyle`）只换拼音行那条线的画法，格子尺寸不动：
`grid` 虚线格（默认）、`under` 下划线、`paren` 小括号、`box` 长方格。
四种都是 `.cell-py` 的伪元素，`ui.js` 只负责把 class 挂上去。

**空段符号**（`□`）在词语文章页生效：单起一行只写 `□`，那一行就留成空白格，
写几个空几行。`genStage` 里 `isBlankLine()` 先认出来，直接铺满一行空格子再 `continue`。

**逐字注音**（`form.pinyin_fix`）是 pinyin-pro 的补丁口。汉字页「改拼音」展开一排小格子，
一个字一个输入框，`{ 字: 'pīn' }` 只存改过的；改回跟自动注音一样就删掉那个键。
`genHanzi` 里先查这张表，查不到才用 pinyin-pro 的结果。

顺手修了一个老 bug：`genHanzi` 原来按「第几个不重复的字」去取拼音，
内容里一出现重复字，后面的音就全串了一位。现在按 `pinyinList` 的分位对齐取。

## 配置的保存与搬家

每个页面的参数改完自动存本机，刷新还在。这件事统一在 `static/store.js` 里的 `Z.settings`：

- **页面自描述 schema**。每个 `page.*.js` 在 `DEFAULTS` 底下写一行
  `Z.settings.define('xxx', { label, defaults: DEFAULTS, inputs: ['content'] })`，
  store 不复制默认值，也不猜字段。
- **`inputs` 是输入类**：正文（`content`）、逐字注音（`pinyin_fix`）这类不落盘、也不进导出的 JSON。
  表格的排版规则（比如 `row_pattern` 间隔描字）算配置，照常保存。
- **清洗靠默认值的类型**。只认 `defaults` 里声明过的键，`typeof` 对齐默认值 ——
  删过的旧字段、手改坏的 json 自然出局。
- **保存挂在 `useGen` 的防抖 watch 上（300ms）**，不挂在 `generate` 里：
  以前校验不过（比如正文清空）就直接 return，顺带把刚改的格型颜色一起丢了。

顶栏齿轮里是出口和入口：导出 JSON（带亮暗主题）、导入 JSON、恢复默认。
导入和恢复都会整页刷新 —— 页面各自持有一份 `form`，逐页去改容易留下半新半旧的中间态。

## 三个约定

- **数据模型渲染，不拼 HTML 字符串**。`utils.js` 的 `gen*` 函数算出每页有哪些格子，`ui.js` 的组件负责画。原站是 PHP 返回 HTML 再 `v-html`，改一个格子样式得动后端。
- **分页按块切**。一个字的所有练习行是一个块，`paginateBlocks` 保证它不会被页边界切断。
- **纸张锁 297mm**。预览和打印共用同一套尺寸，`app.css` 里的 `@media print` 只负责把界面藏掉。
- **英文格的字号不写死**。`utils.js` 的 `Z.GLYPH_METRICS` 里放着六款英文/拼音字体的 asc / xh / desc 和逐字宽度，`enLayout()` 按它算出字号与两条内线的位置。换字体、调行高都不用再改数字。

## 移动端：适配层 + 设置/预览双 Tab

窄屏（`max-width: 760px`）只作用于屏幕，打印不受影响。三件事：

- **适配层**。触控目标落在 34~38px（`.seg button` 34 / `.chip` 34 / `.icon-btn` 36），
  桌面那档 33px 太矮、44 又铺张，这一档好按又不占地方；
  输入框一律 16px，否则 iOS Safari 聚焦会整页放大且退不回来；
  顶栏吃 `env(safe-area-inset-*)`；顶栏在手机上拆成两行 ——
  品牌 + 图标一行、8 个导航入口独占一行横滑（挤成一行的话导航只剩几十像素）。
  整屏留白也整体收一档（页边 10px、卡片内 11/12px、区块间距 10px），
  顶栏 84px、底部栏 53px，比原来各矮十几像素，设置区一屏能多看两三行。
- **设置 / 预览 双 Tab**。`.split` 的两栏轮流显示，开关是 `html[data-mpane]`，
  由 `ui.js` 的 `<z-mbar>` 控制：底部固定一条栏，左边切栏、右边常驻「生成 / 打印」。
  `z-mbar` 的状态是模块级的，八个页面各插一个标签就行，动作由 `useGen` 注册进来。
  「生成」点完自动跳到预览 —— 改参数、看纸，两下。
- **纸张按屏宽缩放**。`index.js` 的 `fitSheet()` 量一次「210mm = 多少 px」，
  按纸槽 `.preview-body` 的真实宽度反算缩放比写进 `--sheet-zoom`，
  320~768 各档都刚好一张纸铺满；打印时强制 `zoom: 1`。

### 多行选项：`.opt-many`

设置区里选项多的控件（6 个字体、8 种格型、11 档描字、色板…）在手机上折成两三行，
设置区凭空长高一截。所以 `ZSeg` / `ZColors` / `ZFonts` 会按选项数量自动挂 `.opt-many`
（阈值 4），窄屏下这个类改成 `flex-wrap: nowrap` + 横向滚动 + 右侧渐隐。
桌面端的折行行为完全不变。

新增控件想吃到这个待遇，只要在选项数量够多时挂上同名类即可。

## 每行格数：12 / 13 两档

汉字字帖、数字字帖、空白练习纸共用一档「每行格数」：12 格常规、13 格密排；
词语文章多留了 8 / 10 两档窄列 —— 抄古诗时一句一行比分段折行好认。
英文与拼音页有自己的两档（12/13 格、8/10 格），原因见下面「英文格为什么这么宽」。

关键在**这不是单纯多一列**。纸宽固定 210mm，12 格那档左右各留 13mm，版心 184、格区 180，
每格 15mm。改成 13 格如果还按 180 算，每格只剩 13.85mm —— 比常规档瘦一圈，格子看着是「压扁」的。

所以 13 档会同时把左右页边距从 13mm 收到 10mm，格区给到 188mm：
`188 / 13 = 14.46mm`，落在「跟 12 档差不离」的 14.2~14.6 区间里。
这个宽度是 `Z.gridWidthOf(cols)` / `Z.padXOf(cols)` 一处算的，
`gen*` 把它写进 `doc.gridWidth` 与 `doc.padX`，`ZSheet` 照着设内边距 —— 纸张尺寸不动。

## 英文格为什么这么宽

老版英文/拼音格固定 **5 列**，每格 35mm。可四线三格的字号是由**格高**推出来的
（`Z.enLayout` 只管高度，宽度只决定「放不放得下」），手写体一个 `Aa` 才 8mm 宽，
右边空掉四分之三 —— 那份余量本来是给 `congratulation` 这种长单词留的，
字母表和一个 `apple` 根本用不上。所以看着就是「格子莫名其妙这么宽」。

现在 `genEnglish` 按内容反算列数：

- 字母表：直接铺满 12 列（15mm 一格，跟汉字格同宽）
- 单词表：每格宽 = 最长的那个词占的宽 + 2.4mm 呼吸位，夹在 15~35mm 之间，
  列数按它反算，余量再平摊回格子，整行铺满。所以 `apple` 是 12 列 15mm，
  `apple banana orange` 是 9 列 20mm，`congratulation` 才回到 5 列 35mm
- 词太长、格子撑到上限之后，交给 `ZCellEn` 里那个「长词自己缩字号」的兜底

拼音页同理但不能照搬：一个音节（`zhuang`、`ying`）塞一格，12 列会把字压到 5mm 以下描不动，
所以它单独两档 8 格（22mm）/ 10 格（17.6mm）。

## 英文/拼音格的排版

四线三格的字号是量出来的：

```
size = (格高 - 0.3mm) / (asc + desc)     # 升部顶贴格顶、降部底贴格底
上边线 = asc - xh                        # 小写字母正好卡进中格
下边线 = asc                             # 基线
```

`asc` / `xh` / `desc` 是字体文件里量出来的真实字形高度（`Z.GLYPH_METRICS`），不是估的。以前每款字体手调一个 px（17 / 20 / 22），各家 x 高度差近一倍，纸上就是一溜小字浮在格中间。

加一款英文字体的话，用 `fontTools` 量一下这三个数、按 `Z.EN_CHARS` 顺序把字宽抄进 `adv`，再往 `Z.EN_FONTS` 加一条即可。

## 素材合集

顶栏右上角的「素材合集」是一堆现成的练字素材：小学一到六年级上册/下册生字表（11 份）
加国学三篇（三字经、弟子规、千字文）。按年级分页签，点开一条，正文摊成一个个紧凑小方格。

这一页只是**参考书**，不跟任何字帖页面搭线 —— 不写 localStorage、不发事件、不跳路由。
用户看点方格挑字，点中的高亮，再点取消，按「一键复制」把选中的字和标点带走，
自己去粘到汉字字帖或词语文章里。一个都不选时，「一键复制」就是整篇。

不自动填入是刻意的：素材有 14 份、目标页有 6 个，谁该填到哪儿说不清，
而复制粘贴是用户本来就懂的动作，不用教。

- 选中状态只记字符在全文里的序号，跟排版无关；复制时按原文的行把这行里选中的字符拼回去，
  国学那种一句一行的，粘贴出来还是一句一行。
- 复制优先走 `navigator.clipboard`；双击 `index.html` 打开是 `file://`，不算安全上下文，
  API 直接不可用，这时退回 `textarea + execCommand('copy')`。

## 数字字帖：字形不是字体，描点也不是描边

原站（E字帖/zivip）的数字模板用的不是字体文件，而是一套按字形存的矢量数据：
每个数字一份 `strokes`（闭合轮廓）+ `medians`（运笔线），跟汉字笔顺数据同一种存法。
所以「把它的数字字体搞过来」这件事的真实结果，是把这套字形拿来自己画：

- `data/num.js`（23KB）放着两套字形：`plain`「专用数字」（瘦长）与 `alpha`「字母数字专用」（更圆），
  各 10 个数字，含轮廓、运笔线和算好的描点。
- 同一个字号下，一套字形的 10 个数字共用一个包络框（`box`）缩放 —— 各按自己的包围盒缩，
  「1」就会被撑成跟「8」一样宽，一页数字胖瘦不齐。
- 因为是矢量画的，十一档描字全都出得来（汉字那边得是「笔顺」格式才有笔心线），
  放大到 A3 也不糊。字体文件只能填色，这些一样都做不到。

**描点（原站叫「圆点画」）是怎么做的**：不是把字形变成虚线，是沿运笔线摆一串圆点，
每个点的半径取「该点到本笔轮廓的最近距离」—— 于是横细竖粗，点的粗细跟着字形肥瘦走。
具体算法（从原站 `gezi.js` 里的 `makedzzi()` 原样搬的，离线脚本跑一遍：

```
沿 medians 从 10 开始以 (r + 60) 为步长前进：
  在轮廓上求这个点到整条轮廓的最小距离（原站是 100 步粗搜 + 回退逼近，笔画一长
  就搜不到真正的最小值，点会一律顶到上限 35；我们改成在整条折线上精确求距，
  反正是离线算，一个字多做几百次点到线段距离，换来的才是真的「横细竖粗」）
  r = clamp(最近距离, 12, 35)；相邻点 r 突增 1.4 倍以上时把 r 打八折，避免忽然鼓一个包
沿运笔线摆满后，若离笔尖还差 20 以内，补一个 r=15 的收笔点
```

原站是运行时现算的：一个字要做几千次 `getPointAtLength` 查询，所以它每次切到「圆点画」
都要弹一句「正在生成圆点数据，请稍候」。我们沿用同一套算法，但**在仓库里离线算好存成数据**
（每个数字 20~40 个点，扁平存 `[x, y, r, ...]`；汉字那 6763 个字的描点同样离线算好，
见 `data/medians/`），打开即用、零等待。

排版沿用汉字字帖那一套：`Zu.genNumber()` 出格子，`<z-cell-num>` + `<z-glyph-num>` 画字，
格型、页脚、订正格、颜色都跟汉字页共用同一批选项。

## 数据

- `data/strokes.js`：6763 个 GB2312 字的笔画路径，base36 增量编码。只建「字 → 偏移」索引，用到才解码（100 字约 1ms）。
- `data/pinyin-pro.js`：pinyin-pro UMD，词组级多音字判断。
- `data/num.js`：0-9 两套数字字形（轮廓 + 运笔线 + 描点），见上一节。
- `data/medians/`：6763 个汉字的笔心线 + 描点，跟 `data/strokes/` 同号分片（各 512 字一片，
  共 41 片，合计 4.4MB）。编码跟笔顺一样是 base36 增量；描点每点三个数（x/y/r），
  r 是「该点到本笔轮廓的最近距离」，离线算好存着 —— 原站是运行时用
  `getPointAtLength` 现算才要弹「正在生成圆点数据」，我们打开即用。
  取法：`Zu.mediansFor(字)` → `{ s: 笔心线, d: 描点 }`，分片没到返回 `null` 并自己补拉。

## 控笔练习

`static/fonts/pen/PenControl.woff2`（4.3KB）是一个图标字体，码位对应 32 个线条图形：
`123456789ABCDEFGHIJKLMNOPQRSTUVW`（没有 `0`、`X`、`Y`、`Z`）。

这些图形天生就是「一个格子」的尺寸，所以不做 SVG，直接把字符当文字画：
`static/page.pen.js` 出表单，`Zu.genPen()` 排版，`<z-cell-pen>` 渲染。
换格子大小就是改 `font-size`，打印出来仍然是矢量的。

**输入方式是一个 textarea**，不是「勾选一串图形」。一行一个图形字符，回车就是一行空白，
所以复制、剪切、粘贴、删掉某一行都跟编辑普通文本一样。下面的图形按钮点一下插到
**光标所在位置**（点按钮时输入框会失焦、`selectionStart` 会归零，位置自己记着）；
从没点进过输入框就插到末尾。一行里写几个字符就是几行纸，小写 `a-w` 自动转大写。

**每行格子是铺满的**。格子边长只是基准：先按 `184mm / (边长 + 间距)` 反算列数，
再把 184mm 摊给这些列（`doc.cellW`），行数同理按摊出来的列宽反算 ——
不然右边会剩下半列空地，纸上看着像没印完。想让「前面描红、后面自己写」，
把「描红格数」从 0 改成 6 就行，那 6 格之后留白。

一个坑：字体的线条是「细长矩形」，横线只有 0.9% em 高，12mm 的格子算下来不到 0.02mm，
屏幕上直接消失、纸上也会被打印机吃掉。所以 `.cell-pen` 加了 `-webkit-text-stroke: .07mm`，
落在纸面上大约一根细线的粗，正好适合描。
